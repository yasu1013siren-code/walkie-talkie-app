# 📻 インカムアプリ (WebRTC + Socket.io)

Android正式採用版 **0.2.3** を採用しました。Bluetoothイヤホンの通話ボタンによる送信切替と、画面消灯中の送受信に対応します。使い方・更新・ビルドは [Android版の説明](android/README.md) を参照してください。以下はWebブラウザ版の説明です。

スマートフォンのブラウザで使える、プッシュトゥトーク方式のインカム(トランシーバー)アプリです。
同じ「ルームID」を入力した人同士で、ボタンを押している間だけ声が届きます。

- 音声通話そのものは **端末同士が直接つながる(P2P/WebRTC)** ため、サーバーの通信量は少なく済みます
- サーバーは「誰と誰をつなぐか」を仲介する**シグナリングサーバー**としてのみ機能します
- ルーム内は複数人(3〜5人程度が目安)対応です

---

## 1. 動作イメージ

1. スマホでURLを開く
2. ルームID(好きな文字列。例: `family01`)を入力して「参加する」
3. 同じルームIDを入力した人同士が自動で接続される
4. 画面中央の丸いボタンを**押している間だけ**マイクがオンになり、他の参加者に音声が届く

---

## 2. 必要なもの

- Node.js 18以上が動くサーバー環境(下記のホスティングサービスでOK)
- **HTTPS環境**(スマホのブラウザはHTTPS(またはlocalhost)でないとマイクを使わせてくれません。下記のホスティングは基本的に自動でHTTPS化されます)

---

## 3. デプロイ方法(おすすめ: Render)

WebSocket(Socket.io)を使うため、**常時起動できるサーバー型のホスティング**が必要です。
Vercelのような「サーバーレス」サービスは常時接続に向かないため非推奨です。

### Renderでのデプロイ手順

1. このフォルダの中身を GitHub リポジトリにアップロードする
2. [Render](https://render.com/) にログインし、「New +」→「Web Service」を選択
3. 先ほどのGitHubリポジトリを選択
4. 以下の設定にする
   - **Build Command**: `npm install`
   - **Start Command**: `npm start`
   - **Instance Type**: Free でOK(常時起動が必要なら有料プラン)
5. 「Create Web Service」をクリックすると数分でデプロイされ、`https://xxxxx.onrender.com` のようなURLが発行されます
6. スマホでそのURLを開けば利用できます

### その他の選択肢

- **Railway**(https://railway.app/) も同様の手順でデプロイ可能です
- 自前のVPS(さくらVPS、ConoHaなど)の場合は、`npm install` → `npm start` の後、Nginxなどでリバースプロキシ+HTTPS化(Let's Encrypt)してください

## 6. カスタマイズのヒント

- **参加人数の上限を増やしたい**: 現状は全員が直接つながるメッシュ型構成のため、人数が増えると各端末の負荷が上がります。10人以上を想定する場合は、SFU(mediasoup, LiveKitなど)への切り替えを検討してください
- **常時通話(トランシーバーでなく普通の通話)にしたい**: `client.js` の `startTalking` / `stopTalking` を呼ばず、参加時に `track.enabled = true` のままにすれば常時通話になります
- **ルームにパスワードを付けたい**: `server.js` の `join-room` イベントで簡単なパスワードチェックを追加できます
- **通話ログや文字起こしを付けたい**: 別途、音声認識APIとの連携が必要です(この構成には含まれていません)

---

## 7. 注意事項

- マイクの使用許可はブラウザ側で毎回求められます。許可しないと使用できません
- iOSのSafariでは、画面ロック中や他アプリに切り替えると通話が切れることがあります(ブラウザアプリの制約)
- 通信環境によっては音声が途切れることがあります

## スマホ・Bluetooth・バックグラウンドの対応状況

- 「ホーム画面に追加」でアプリ風に起動できます。PWAのキャッシュは画面の読み込み用で、オフライン通話には対応しません。
- Bluetoothイヤホンは、先に端末の設定でペアリングしてください。ブラウザが `setSinkId` に対応する場合のみ出力先を画面から選べます。iPhoneなど非対応ブラウザでは端末側の音声出力設定を使用します。Bluetoothマイクの選択や物理ボタンによるPTTはブラウザと機種に依存し、この版では保証しません。
- 参加中は対応端末で画面のスリープを抑制します。画面が見えなくなったら誤送信防止のためPTTを解除します。画面ロック中や他アプリ使用中の受信・通話維持はWeb版では保証できません。iOSで確実に常時受信するにはネイティブアプリとApple Push to Talk framework、通知用バックエンドを追加してください。
- 異なるネットワークでP2P接続できない場合にはTURNサーバーが必要です。現在の設定は公開STUNのみです。
- ルームIDを知る人なら参加できます。店舗運用前にスタッフ認証とアクセス制御を追加してください。

### イヤホンボタンの送信切替

参加後、ブラウザがイヤホンのメディア操作をこのページに届ける場合は、再生ボタンで送信を開始し、停止ボタンで送信を止められます。マイク切替操作に対応する端末では同じボタンで交互に切り替わります。画面のPTTボタンは従来どおり押している間だけ送信します。画面に「イヤホン操作を検出」と表示されれば入力が届いています。

イヤホンの通話ボタンは電話の応答・終話としてOSに処理され、Webページに届かない機種があります。また、Media Sessionの対応表示だけでは実機動作を保証できません。送信中は画面でも赤く表示されるので、最初に2台で音声と停止を確かめてください。通信切断、画面が非表示になった時、退出時には送信を停止します。画面ロック中の操作は保証しません。
