# 実機試験と合格基準

今回の実行環境にAndroid実機・イヤホンはなく、以下は未実施。自動テストでBluetoothの成功は判断しない。

## 記録する組合せ

端末名・OS/API・アプリcommit/版・署名証明書指紋・イヤホンのメーカー/型番/ファームウェア・ボタン設定・音量/増幅値・回線・参加人数・日時・試験者を記録する。S10/M2は販売名だけで同一製品とみなさず、現物の型番を残す。基準のSCG21/Android 16と、別メーカー端末、Android 8〜15の代表端末で試す。ARM64と必要ならARMv7を確認。

## 手順と判定

| 試験 | 手順 | 合格条件 |
|---|---|---|
| 従来利用 | 新サーバーの互換設定で旧0.2.4と新クライアントを店舗ID空欄・同じルームへ参加 | 両方向の音声・参加者表示・退出が動く |
| 招待 | 正しいコード、不正コード、期限切れ、店舗違い、部屋違い、店舗ID空欄、定員超過を順に試す | 正しい招待のみ参加。拒否時に送信できず、マイクと通話セッションを停止 |
| 店舗分離 | 同名ルームを別店舗で開く | 声・参加者・送信状態が店舗間に届かない |
| 基本通話 | 2台、画面長押し・固定送信・停止、同時送信 | 一方ずつ音声が届く。送信停止後のマイク音声が漏れない。クラッシュなし |
| S10/M2 | 各型番でボタンON、押して開始・再度押して停止を20回。停止から約1秒置き、急な連打も確認 | 意図せぬ送信開始なし。開始／停止と音声が一致 |
| 消灯・背景 | 送信固定後と停止状態で各30分消灯。別アプリ・通知操作・省電力ON/OFF | 両方向の音声を保ち、通知で停止／退出できる。端末制限があれば対応表へ記載 |
| 外部通話 | 本物の着信・応答・拒否・終了、Bluetooth切断／再接続 | 他の通話を妨害せず、勝手に送信を再開しない |
| 増幅 | 同じ相手・発話・端末音量で1/1.5/2/2.5/3倍、再起動・再参加・相手再接続 | 初期2.0、選択保存・即時反映。聞き取りと音割れの評価を記録 |
| 再接続 | Wi-Fi↔携帯、機内モード復帰、サーバー再起動 | 送信停止で再接続。正しい招待を再検証。相手と音声を復旧 |
| TURN強制中継 | 検証ビルド/ブラウザだけでrelay-onlyを指定し、双方別回線。UDP・TCP/TLSを順に試す | WebRTC統計の選択candidateがrelayであることと音声疎通を確認 |
| TURN更新・期限 | 1時間超継続し、新しい相手も途中参加。招待期限を短く設定して観察 | 一時資格情報が更新され、新規peerも接続。招待失効で正規端末は終了 |
| 長時間・人数 | 2/5/10台と店舗の想定最大人数で営業相当8時間 | クラッシュ・過熱・再接続・遅延・電池消費を定量記録、許容値を事業者が決定 |
| 秘密と停止 | 退出・アンインストール、ログcatとホストログを確認 | 招待・TURN資格情報・鍵がログに出ず、退出後に送信なし |

TURNが設定されているだけでは中継成功とみなさない。統計のcandidate種別、疎通、資格情報の更新を確認する。中継強制は試験用であり、本番は既存の直接通信優先を維持する。

## 販売判定

結果表に「合格／不合格／未実施」と再現手順を残す。未試験の端末・イヤホンを対応済み一覧へ載せない。現在の報告は利用者による0.2.3系のボタン操作成功があるが、今回追加した招待・TURNを含む組合せは未確認。
