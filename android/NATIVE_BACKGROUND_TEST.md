# スタッフインカム 0.2.0 試験版

## 変更点

音声・WebRTC接続・Socket.IO接続をAndroidのIntercomServiceへ移しました。WebViewを使わず、Activityの表示状態と独立して送受信します。マイク・音声再生のフォアグラウンドサービス、通話通知、CPUのWakeLockをルーム参加中のみ使用し、退出時に解放します。

Bluetoothの通話用デバイス（SCO / LE Audio）を優先して選択します。有線・USBヘッドセットも候補にし、イヤホンがない場合は端末スピーカーへ切り替えます。通信切断時は送信を停止し、再接続後も受信待機に戻ります。再接続の際に自動でマイク送信を再開しません。

アプリIDは jp.es.staffintercom.preview です。既存0.1.12の署名鍵がないため、元のアプリと並べてインストールできる試験版にしました。既存アプリを削除せず試せます。同じ端末で旧版と試験版を同時にルームへ参加させないでください。

## 操作

1. Bluetoothイヤホンを端末に接続します。
2. アプリを開き、ルームIDと名前を入力して参加します。
3. マイク、付近のデバイス、通知の許可を求められたら許可します。
4. 受信は参加中ずっと有効です。「押しながら話す」は押している間だけ送信します。
5. 「送信を開始」は送信を固定します。もう一度押すか通知の「送信を停止」で停止します。この操作による送信は画面消灯でも継続します。
6. 通知の送信切替と退出は、アプリ画面を開かずに使えます。ロック画面の操作には端末側のロック解除が必要な場合があります。
7. 終了時はアプリまたは通知の「退出」を押します。

診断ログは通常画面に表示しません。

## 実機確認（未実施）

使用端末：Samsung SCG21 / Android 16、Bluetoothイヤホン S10。

- 2台を同じルームへ参加させ、双方の音声をイヤホンで受信できること。
- イヤホンのマイク部分と本体マイク部分へ別々に話し、実際の入力経路を確認すること。出力先表示だけでは入力経路を確定できません。
- 受信待機中にホームへ戻る → 画面を消す → 1分後と10分後に相手の音声を受信できること。
- 送信固定中に画面を消し、相手が音声を受信できること。通知で送信を止めた後は相手に声が届かないこと。
- Bluetoothを切断して再接続し、接続再確認後に双方の送受信が戻ること。
- Wi-Fi切断・再接続で再参加し、送信が勝手に再開しないこと。
- 電話着信時に送信が停止し、通話終了後に接続再確認で音声が戻ること。
- 退出後に通知が消え、端末のマイク使用表示が終了すること。
- 旧Web版と試験版の間でも同じルームで送受信できること。

## 残る確認・制限

S10では過去のテストで、通話用Bluetooth経路使用中のMediaSessionボタンが届かず、Telecomの応答・切断のみ届きました。この試験版はMediaSessionの操作を受けますが、S10のボタン操作の問題は解決を確認していません。通知や画面から送信を切り替えて、まず音声とバックグラウンド動作を検証します。Telecomと実際のインカム通話の統合はこの試験版に含みません。

STUNのみを使う既存サーバーと同じ構成です。TURN中継が必要なネットワークでは音声がつながらない場合があります。OSからの強制停止やプロセス終了後には自動でマイクを再開せず、アプリを開いて再参加します。バッテリー制限下・長時間・端末固有の動作は実機検証が必要です。

## 0.2.2：S10ボタン操作・試験

画面の「S10ボタン操作を使う（試験）」をONにして参加します。参加後にONにすることもできます。通常の診断ログは表示せず、ボタン待機状態だけを表示します。

- S10の通話ボタンで応答すると送信を開始します。
- もう一度押して切断すると送信だけを停止し、ルームの受信は継続します。
- 約1秒後に、次の応答を受け付ける待機状態を登録します。連打はせず、「S10：待機中」の表示を確認して繰り返します。
- 画面・通知からの停止でも次の待機へ戻します。退出・通信切断・操作OFFでは待機の再登録を取り消し、古い操作で送信を開始しないようにします。
- 他の電話がある場合やAndroidに通話登録を拒否された場合は、操作をOFF→ONして再登録します。

この方式はAndroidの自主管理VoIP通話として待機・応答・切断を登録します。実際の電話番号へ発信するものではありません。端末の通話表示が出たり、S10のファームウェアが着信待機音を鳴らしたりする可能性があります。アプリ側の待機通知は音・バイブなしです。

v0.2.1でSCG21 / Android 16 / S10の画面消灯中の送受信はユーザーにより確認済みです。v0.2.2のTelecom操作と音声経路の組み合わせは実機未確認なので、ボタンを3往復操作し、各停止後も相手の声が聞こえるか、画面消灯中でも開始・停止できるかを確認します。受信に支障がある場合はS10操作をOFFにして音声接続を再確認します。

0.2.2の確認：RobolectricによるAndroid通話状態テスト5件成功（反復操作、重複応答、停止後の再登録、古い操作の排除、通信切断、画面操作との連動）。APKビルド・必要権限・ConnectionService登録・署名検証・配布した0.2.1との署名一致を確認しました。S10の実ボタンとバックグラウンド音声の組み合わせは実機確認が必要です。

## 0.2.3：S10待機による音声停止の修正

ユーザーのSCG21 / Android 16 / S10で、0.2.2はS10操作ONでルーム参加直後に「他の通話」と表示され音声が停止、OFFでは送受信できました。AudioManagerのフォーカス喪失を、自分のTelecom待機・通話登録中にも無条件で外部通話と扱っていた処理を修正しました。待機登録中・応答後は自分のTelecom登録を音声利用の経路として扱い、AudioManagerのフォーカス再要求でTelecomと競合しないようにしています。

ConnectionService側で通話フォーカスを失った場合は別の通話による中断として送信を止め、待機登録・自動再送信を止めます。自分の切断後に届くフォーカス喪失では次の待機を取り消しません。別の通話終了後はS10設定をOFF→ONして接続を再確認してください。

検証：Robolectricの回帰テストで、自分の登録中・待機中のフォーカス喪失、通常のフォーカス喪失、Telecomの中断、既存の反復操作を確認します。実機では、ONで参加直後の受信、画面送信、S10で開始→停止を3回、各停止後の受信、画面消灯中の操作、外部電話着信時の送信停止を確認してください。Androidのフォーカス通知だけでは操作元は特定できないため、端末固有の通知順・着信待機音・音声経路は実機確認が必要です。

0.2.3の確認結果：Robolectricテスト8件成功、APKビルド成功。アプリID jp.es.staffintercom.preview、versionCode 17、versionName 0.2.3、APK署名検証成功・配布した0.2.2と署名一致。S10実機での修正結果は未確認です。
