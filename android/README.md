# Android版インカム（実機検証用）

公開中のインカムWeb画面をAndroid WebViewに表示し、MediaSessionで受け取ったイヤホンのメディアボタンを送信切替に渡します。ブラウザ版でボタンが反応しない場合の実機検証用です。新しい通話サーバーは不要です。

## 入手・起動

GitHubの **Actions → Android debug APK → 最新の成功した実行 → staff-intercom-debug-apk** からAPKを取得します。デバッグ署名の検証用APKです。Android Studioでこの `android` ディレクトリを開き、JDK 17 / Android SDK 35でビルドすることもできます。

アプリを開いてマイクを許可し、ルームに参加してください。イヤホンボタンの入力が届けば、画面に「イヤホン操作を検出」と表示されます。1回押して送信、もう1回押して停止を2台で確認してください。画面のPTTボタンは押している間だけ動作します。

## 現在の範囲

- Android版のみ。iPhoneにはインストールできません。
- ボタンがAndroidからMediaSessionに届くイヤホンで動作します。通話専用ボタンや音声アシスタントに割り当てられたボタンは届かない場合があります。
- 画面が閉じると送信を停止します。画面ロック中・他アプリ使用中の受信維持は未対応です。
- WebViewでのBluetoothマイク経路は機種ごとに実機確認が必要です。既存のChromeブラウザで通話できても、WebViewで同じ結果になるとは限りません。
- Android 8以降のメディアボタンの宛先選択に合わせ、ルーム参加中かつ画面表示中は無音のローカル再生と音声フォーカスを維持します。別の音楽アプリの再生は一時停止される場合があります。イヤホン固有のボタン割当や音声アシスタント操作は引き続き実機確認が必要です。
- デバッグ署名のAPKを運用配布しないでください。店舗運用前に署名、認証、通話安定性と割込み動作を確認してください。

## v0.1.6 イヤホン診断

Androidアプリの画面下に診断欄を表示します。Render側の更新は不要です。

1. v0.1.6をインストールし、ルームに参加します。
2. 診断欄の「消去」を押し、イヤホンのボタンを1回押します。
3. 「コピー」で内容を共有するか、診断欄のスクリーンショットを送ります。
4. 2回押し・長押しも、それぞれ消去してから試してください。

表示内容は受信元（画面 / MediaSession）、キー名・番号、押下 / 解放、PLAY / PAUSE / STOPの受信、ルーム・送信状態、MediaSession、音声フォーカス、操作受付用の無音再生、マイク要求、Web画面への切替要求です。画面経由のキーにはスマホ本体の音量・戻る操作なども含まれます。件数は押した回数ではなく受信イベント数です。

キー受信と音声操作受信が両方0なら、このアプリで信号を受信できていません。Android内の送信先やイヤホン側の原因まではこの表示だけでは確定できません。キー受信だけが増える場合もあるため、両方を確認してください。Web切替要求の called は関数の呼出成功を意味し、実際に相手へ音声が届いた証明ではありません。診断履歴は最新12件で、アプリ再起動時に消えます。
