# スタッフインカム Android 0.2.4

2026-10-02に正式採用した0.2.3の音声通信・ボタン操作を維持し、受信音声の増幅を追加しました。初期値は2倍、画面の「受信音声の増幅」で1〜3倍を0.5刻みで調整できます。設定は次回起動・再参加・相手の再接続にも反映します。倍率は信号の増幅量で、聞こえる音量がそのまま倍になるとは限りません。音割れ時は倍率を下げてください。

音声処理はWebRTCの受信AudioTrack.setVolumeを使い、送信トラックや端末の通話音量は変更しません。画面のバージョン表示をBuildConfigと連動し、試験版の表示を整理しています。
## 更新と起動

更新APKは `staff-intercom-v0.2.4.apk`。アプリIDは `jp.es.staffintercom.preview`、versionCode 18、versionName 0.2.4です。保存済みの新しい署名鍵で署名します。新しい鍵で署名した `staff-intercom.apk` と同じ署名なので、その版からは上書き更新できます。古いデバッグ署名版からは初回だけ削除・再インストールが必要です。ルームID・名前・ボタン設定・増幅設定は、上書き更新時には維持します。
1. Bluetoothイヤホンを接続し、アプリを開きます。
2. ルームIDと名前を入力します。通話ボタンを使う場合は「イヤホンの通話ボタンを使う」をONにします。M2も同じ設定で試せますが、全機種対応を確認したものではありません。
3. マイク・付近のデバイス・通知の権限を許可し、同じルームへ参加します。
4. 「S10：待機中」の表示後、通話ボタンで送信を開始し、もう一度押して停止します。停止後、次の操作の準備に約1秒かかります。
5. 「押しながら話す」は押している間だけ送信します。「送信を開始」は送信を固定し、画面を消しても続きます。通知からも停止・切替・退出できます。
6. 終了時は「退出」を押します。

受信は参加中、画面消灯や他アプリ表示中も継続します。通常画面には診断ログを表示しません。イヤホン側で着信待機音が出る場合があります。

## 接続と中断

音声・WebRTC・Socket.IO接続はAndroidのフォアグラウンドサービスが管理します。Bluetooth通話用経路を優先し、イヤホンがない場合は端末側へ切り替えます。

通信が切れると送信を停止します。再接続後は受信待機に戻り、送信は自動再開しません。別の電話で中断した場合は、通話終了後にボタン設定をOFF→ONし、「Bluetooth接続を再確認」を押します。強制停止後はアプリを開いて再参加します。

接続先は既存サーバー `https://walkie-talkie-app-42l7.onrender.com`。STUNのみの構成のため、TURN中継が必要なネットワークでは接続できない場合があります。ボタン信号・音声経路は端末とイヤホンの組み合わせに依存します。

## ビルドと検証

JDK 17、Gradle 8.13、Android SDK 35 / build-tools 35.0.0。

```sh
gradle -p android :app:testDebugUnitTest :app:assembleDebug --no-daemon
```

新しい署名鍵とパスワードは非公開のバックアップ `staff-intercom-signing-backup-20261002.zip` または同内容の `intercom-key-backup.zip` に保存しています。秘密鍵・パスワードは公開GitHubへ置きません。APKをビルド後、バックアップのPKCS12鍵で署名し、証明書SHA256を照合します。GitHub Actionsで作られるデバッグAPKはこの配布鍵で署名されません。

WebRTCの受信増幅API： https://webrtc.googlesource.com/src/+/main/sdk/android/api/org/webrtc/AudioTrack.java

0.2.4では初期増幅値・設定の永続化・異常値の復旧と、既存の通話ボタン回帰テストを確認します。実機での受信音量・音割れはユーザー確認が必要です。
0.2.3作成時にRobolectricテスト8件・APKビルド・署名検証に成功し、0.2.2との署名一致を確認済みです。0.2.1のSCG21 / Android 16 / S10での画面消灯中の送受信はユーザー確認済み。0.2.3のボタン操作成功と正式採用は2026-10-02のユーザー報告に基づきます。最新報告では使用イヤホンの機種は明示されていないため、個々の機種の動作確認として断定しません。過去の経緯と詳細テストは [NATIVE_BACKGROUND_TEST.md](NATIVE_BACKGROUND_TEST.md) に記載しています。
